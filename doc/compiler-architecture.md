# Архитектура компилятора C для riscA

Проектная запись решений для компилятора (веха M3 из
[emulator-architecture.md](emulator-architecture.md), раздел 11). Источник истины по
инструкциям — [RiscA.MD](RiscA.MD); карта памяти, UART и формат карты символов —
[emulator-architecture.md](emulator-architecture.md). Это не спецификация ISA.

## 1. Выбранный путь

Цель: минимальными усилиями получить рабочий компилятор C, способный собирать простые
консольные утилиты из open source, с возможностью развивать его дальше.

| Вариант | Вердикт |
|---|---|
| Свой компилятор целиком (лексер+препроцессор+парсер+кодоген, C#) | Отклонён. Кодоген под нашу ISA — самая дешёвая часть; дорогой кусок — препроцессор и парсер реального C, а на них первый же open-source пакет и споткнётся |
| Чужой обкатанный C-фронтенд + свой маленький бэкенд RiscA | **Принят.** Фронтенд даёт `cproc` (MIT, полный парсер C99: struct/union/указатели; препроцессор master-ветки делегирует `#include` системному `cpp`), он выдаёт текстовый QBE IR — машинно-независимый и простой. Бэкенд `rcc` — новый C#-проект в SDK: читает IL всех модулей программы, разрешает внешние символы между ними и выдаёт **один** `.rasm` |
| Адаптация lcc (retargetable C-компилятор, порт = файл `mac` + peephole) | План Б. Целостный комплект, но C-код, mediocre кодоген, маски регистров в `regalloc.c` правятся вручную. К нему придём, если IL-путь упрётся |
| Транслятор C→RISC-V→RiscA (QC/chibicc + RV32-маппинг) | Отклонён. RV32 предполагает 32 регистра, смещения памяти до ±2047, `LUI+ADDI` — всё это придётся перекладывать; сопоставимо с бэкендом, но поверх чужих допущений |
| Полный бэкенд LLVM (TableGen) | Отложено на M4+. Появится смысл, когда фронтенд станет узким местом. Тот же C#-бэкенд потом сможет есть LLVM IR вместо QBE IR |

Почему «линковка нет»: бэкенд собирает все единицы трансляции **и** подключенные libc-библиотеки
в один `.rasm` (как `samples/uart.echo.rasm` подключает `lib/uart.rasm`), внешние символы
разрешает сам между модулями. Объектных форматов и `rld` на M3 не появляется.

Конвейер:

```
prog.c ──cpp + cproc-qbe──► prog.il ───────┐
libc-модули (C) ────────────────────────────┤
                                            ▼
                            rcc (RiscA backend, C#, наш)
                                            ▼
                               prog.rasm (+ pool'ы констант)
                                            ▼
                                  rasm ──► prog.bin ──► rasim
```

`cproc` и QBE — MIT, можно вендорить в репозиторий как `third-party/` (решение по
размещению — открытое, см. раздел 9). Домашний сайт cproc (`cproc.orowhy.com`) умер;
официальное местожительство — `git.sr.ht/~mcf/cproc` и зеркало автора
`github.com/michaelforney/cproc` (актуально, собано — см. раздел 2).

## 2. Что такое QBE IR и как на него посмотреть (проверено)

QBE — маленький бэкенд-компилятор (c9x.me/compile, лицензия MIT), принимающий на вход
текстовый SSA-подобный IR («IL») и выдающий Gas-ассемблер amd64/arm64/riscv64. Наш план
использует только **половину**: фронтенд, печатающий IL; сам кодоген QBE нам не нужен —
его роль исполняет наш `rcc`.

Ключевые черты IL (полное описание: c9x.me/compile/doc/il.html):

- сигилы: `$` — глобалы, `%` — temporaries, `@` — блоки, `:` — агрегатные типы;
- типы минимальные: `w` (32 бита), `l` (64 бита, у нас — запрещён), `s`/`d` (float,
  запрещены — в железе нет FPU), `b`/`h` — только в данных и типах;
- определения `data` (строки, таблицы, массивы, `z N` — нули) и `function` с типизированными
  параметрами; определения модулей взаимно рекурсивны — деклараций не нужно;
- тело — блоки с последней командой-переходом: `jmp @label`, `jnz %v, @a, @b`, `ret`, `hlt`;
- трёхадресные инструкции: `add/sub/mul/div/udiv/rem` `(w)`, `and/or/xor`, `shl/shr/sar`,
  сравнения `csltw/cultw/ceqw/...` возвращают 0/1, loads/stores всех ширин
  (`loadsb/storeb/...`), `alloc4` под локалы, `blit`, `call` с типами аргументов;
- **SSA не обязателен**: phi можно не писать, QBE сам приводит; фронтенд может жить в стиле
  «всё в alloc4 + load/store» — ровно то, с чего начинаем в v0;
- `phi`-инструкции существуют, но в v0/v1 бэкенд их не поддерживает — только стиль alloc+load.

Практика (сборка проверена в WSL Ubuntu 24.04, qbe 1.3 из архива c9x.me):

```sh
curl -sSO https://c9x.me/compile/release/qbe-1.3.tar.xz   # sha256 d587905d...cf66e320
tar xf qbe-1.3.tar.xz && cd qbe-1.3
echo '#define Deftgt T_amd64_sysv' > config.h             # make config.h сам генерирует
gcc -O1 -std=c99 -w -o qbe main.c util.c parse.c abi.c cfg.c mem.c ssa.c alias.c \
    load.c copy.c fold.c gvn.c gcm.c simpl.c ifopt.c live.c spill.c rega.c emit.c \
    amd64/*.c arm64/*.c rv64/*.c
./qbe prog.ssa -o out.s && cc out.s && ./a.out            # контрольная сборка под x86-64
./qbe -d A prog.ssa                                       # распечатка IL после каждого прохода
```

В составе qbe есть игрушечный C-фронтенд `minic` — им удобно смотреть IL без cproc
(`cd minic && gcc -o yacc yacc.c && ./yacc minic.y && gcc -o minic y.tab.c`,
затем `./minic < file.c > file.ssa`). Пример, который реально выдал minic для цикла
`while (i <= 10) { s = s + i; i = i + 1; }`:

```
@l1
        %t5 =w loadw %i
        %t4 =w cslew %t5, 10
        jnz %t4, @l2, @l3
@l2
        %t9 =w loadw %s
        %t10 =w loadw %i
        %t8 =w add %t9, %t10
        storew %t8, %s
        ...
        jmp @l1
```

Это же — формат будущих золотых тестов бэкенда (раздел 7): их можно писать руками.

### cproc как фронтенд IL (собрано и проверено)

cproc собран в WSL из зеркала автора (`github.com/michaelforney/cproc`, master 2026):

```sh
curl -sSL -o cproc.tar.gz https://codeload.github.com/michaelforney/cproc/tar.gz/refs/heads/master
tar xzf cproc.tar.gz && cd cproc-master
./configure                        # meson НЕ нужен: Makefile + configure
make                               # (в WSL нет make — компилировали циклом gcc по Makefile)
#   все .c кроме driver.c линкуются в cproc-qbe (фронт), driver.c — в cproc (драйвер)
```

Важные факты про master-cproc (проверено на деле):

- фронтенд `cproc-qbe` печатает IL на stdout/в `-o`; машинный код — за внешним `qbe`
  (`codegencmd` в config.h), флаг драйвера — `-emit-qbe` (не `-emit-il`);
- `#include` в собственном препроцессоре master **не реализован** — драйвер вызывает
  системный `cpp`. Для IL без драйвера: `cpp file.c | ./cproc-qbe -o file.il`
  (**опции до имени файла** — иначе аргументы путаются);
- цели в master только LP64: `x86_64-sysv`, `aarch64`, `riscv64`; `long` и указатели
  зашиты по 8 байт (`type.c`) — см. раздел 3;
- диалект IL: параметры в скобках (`function w $gcd(w %.1, w %.3)`, без `.param`),
  строки `data $.Lstring.N = align 1 { b "...", }`, `alloc` возвращает значение-указатель
  (`%.2 =l alloc4 4` при LP64), switch — бинарное поисковое дерево из `ceqw/cultw`,
  `%` — это IL-инструкция `rem`, variadic-вызов: `%.27 =w call $printf(w $.Lstring.4, ..., w %.24)`.

Цепочка проверена end-to-end: IL из cproc master разобрался нашим qbe 1.3, собрался `cc`
и отработал корректно (`hello from cproc`, `sum=70 gcd=6 cls=2`, exit 70). То есть диалекты
свежего cproc и релизного qbe 1.3 совместны, и наш `rcc` сможет есть этот IL.

## 3. Подмножество IL под 32-битную цель (уточнено)

Решение прежнее: наш бэкенд принимает IL для **ILP32-цели**: все целые 32 бита, все
указатели — `w`; 64-битные `l`-вычисления и float — ошибка компиляции.

Найденное подтверждение (проверено): **ILP32-IL от cproc реально существует**. В форке
`michg/cproc` (meta-репозиторий `michg/cproc_riscv32`, там же `michg/qbe_riscv32` —
бэкенд riscv32imf) в таблице целей есть `rv32`, размеры long/указателя вынесены в
переменную `ptrsize`, и IL для него печатается чисто `w`-модельное:

```
function w $gcd(w %.1, w %.3) {
@start.1
        %.2 =w alloc4 4           ; локал-указатель тоже w
        storew %.1, %.2
        ...
%.27 =w call $printf(w $.Lstring.4, ..., w %.24, w %.25, w %.26)
```

Собрано в WSL (`~/cproc-rv32`), прогон `./cproc-qbe -t rv32 demo.c` — IL выше.
Договор с `rcc`: вход — ILP32-IL именно такого вида; `l` где угодно, кроме операндов
load/store в LP64-диалекте, — ошибка. Для LP64-IL от upstream-master оставлен запасной
переход (исторический): `l` трактуется как «машинное слово» там, где QBE подразумевает
адрес (результат `alloc4`, операнды load/store) — но им пользоваться не планируем.

Что выбирать как фронтенд к M3.0:
(a) форк `michg/cproc` (2022,rv32 уже в таргете; старше master);
(b) upstream-master + портирование патча `rv32` (таргет + параметризация размеров long/
указателя в `type.c`) — порт небольшой, вся логика `ptrsize` в форке уже написана.
Склонность — (b): свежий парсер + наш таргет; решение на M3.0 по живому порту.

## 4. Отображение IL → RiscA

| IL | RiscA | Примечание |
|---|---|---|
| `add/sub/mul/and/or/xor` (w) | ALU reg-reg | reg+imm складывает ALU-imm (`add r, imm7`), при необходимости — `li` + reg-reg |
| константы | псевдокоманда `li Rd, c` | `movi` + до 3 `movl` (цена 1–4), ассемблер (раздел 5) |
| `shl/shr` на константу ≤ 15 | ALU-imm SHL/SHR | спецификация берёт сдвиг из 4 младших бит imm |
| `shl/shr` на переменную | вызов `__shl/__shr/__sar` | runtime-библиотека; спека не даёт сдвига по регистру |
| `div/udiv/rem/urem` | вызов `__divsi3/__udivsi3/__modsi3/__umodsi3` | деления в ISA нет; вычитание/сдвиги, runtime |
| `csltw/cultw` в контексте `jnz` | `SLT/SLTU` + `BNEZ/BEQZ` | слияние «сравнение+переход» — два раза вычитать не нужно |
| `ceqw/cnew` в контексте `jnz` | `XOR Rd, Rs` + `BEQZ/BNEZ` | |
| прочие `c<op>w` в значение | `SLT/SLTU` + арифметика | общий случай, реже |
| `loadw/loadub/...`, `storew/storeb` | `LDW/LDB/STW/STB [Rs+imm3]` | смещение `Imm(3)`: слово в ±28 байт; больше — базовый регистр (раздел 5 ABI) |
| `alloc4` | слоты кадра `[r15+k]` | фрейм ≤ 28 байт; иначе база `r15+K` в начале функции |
| `jmp`, `jnz` | `JR label` (псевдо `j`), `BEQZ/BNEZ` | релаксация при выходе за ±128/±256 инструкций (раздел 5) |
| `ret` | `RET r14` + пролог/эпилог | |
| `call $f(w ...)` | `CALL f` | пул трамплинов для CALL дальше ±1024 слов |
| `copy` | `mov` | |
| `blit` | цикл `memcpy` | размер константный — разворачиваем, большой — call |
| `hlt` | `RET` с заглушкой / остановка машины | |

ABI (фиксируем, совпадает со спекой, раздел ABI, и `samples/lib/uart.rasm` уже так живёт):

- аргументы: `r0..r5` (не более 6 слов в регистрах, остальное — стек, кладёт вызывающий);
- возврат: `r0`; ссылка — `r14`, при вложенном вызове пушится;
- сохраняют callee: `r8..r13`; свободно гадят: `r0..r7` (кром аргументов в момент вызова);
- константы функции — пул после `ret` (спека: «Constants ... at the end of the function
  after ret»), берём `LDI` из пула; далеко — `li` movi/movl;
- variadic: первые аргументы те же `r0..r5`, хвост — в стеке вызывающего; `va_list` —
  12-байтная структура `{стопка, курсор}`. Это наша договорённость, QBE-шные `vastart/vaarg`
  бэкенд реализует под неё; реализуем на M3.3.

## 5. Сначала — ассемблер (веха A1, предпосылка M3)

Бэкенд не должен знать про `movi/movl`, диапазон `LDI` и ограничение переходов — это прячется
в `rasm`. Что добавляем в `src/RiscA.Core/Asm`:

**Псевдокоманды** (правила в `Parser.cs`, токены-синонимы в `Tokenizer`):

| Псевдо | Разворот | Цена |
|---|---|---|
| `li Rd, c` | `movi Rd, hi` + `movl` по байтам вниз до старшего ненулевого | 1..4 |
| `la Rd, label` | `LDI Rd, [@pool_k]` + запись `dw label` в пул функции | 1 + 4 байта пула; если пул дальше ±256 инстр. — инлайн-мини-пул `ldi+jr[+nop]+dw` прямо на месте (адрес всегда в `dw` — задел под таблицу релокации) |
| `j label[, rN]` | `JR` (±1024 инстр.) либо `LDI rN, [@pool_k]` + `JMP rN` | 1..3; rN по умолчанию `r7` (берём как scratch, `lib/uart.rasm` использует его же) |
| `push rN` / `pop rN` (уже реализовано) | макрос стека ABI из `RiscA.MD` дословно: `SUB R15,4`+`STW [R15+0],rN` / `LDW rN,[R15+0]`+`ADD R15,4` | ровно 2; скретча и фиксапов нет, `push r15`/`pop r15` — ошибка |

`db`/`dw` уже есть в парсере (строки, числа, метки) — данные компилятор умеет выдавать сегодня.

**Рефактинг фиксапов.** Сейчас `ParsedInstruction` хранит одну `RefLabel`, а этого мало:
разворот `la` даёт две связанные записи (LDI + dw-слот пула). Меняем `RefLabel` на
`List<Fixup { int InstrIndex; string Label; FixupKind Kind }>` с kinds:
`ImmInstr` (ветки/JR, шаг — инструкция), `ImmWord` (CALL, шаг — слово, цель 4-выровнена),
`PoolRef` (imm9 к слоту пула). Парсер при развороте добавляет фиксапы, вторая проход-петля
применяет.

**Петля релаксации вместо одного второго прохода.** Адреса меняются при разворотах, поэтому
второй проход превращаем в цикл до неподвижной точки (обычно 2–3 итерации, потолок 10,
иначе ошибка с перечислением проблемных меток):

```
повторять:
  пересчёт адресов всех SrcLine
  разрешить фиксапы, разметить выходящие за диапазон
  для выходящих веток:  beqz r, far  ->  bnez r, over; j far; over:
      (инверсия условия + псевдо j, её саму тоже может развернуть следующая итерация)
  для выходящих CALL:   call far     ->  la r?, [@pool_k]; call r?
  добавить/передвинуть пул в конце функции (между последним ret и следующим .func)
пока что-то изменилось
```

Оценка: ~3 рабочих дня с тестами (`tests/RiscA.Core.Tests`: li/la/j развороты, фиксипы,
релаксация длинных веток и дальних CALL, пулы, сходимость).

Продолжение того же принципа «весь мусор знаний о железе — в ассемблере» — веха **A2**
(план в `assembler-architecture.md`, раздел 7): называемые слоты и авто-пролог/эпилог,
`call f(a, b)` со списком аргументов, имена-переменные вместо регистров и регаллок в
`rasm`. Регаллок переезжает из `rcc` в ассемблер: IL одноразовая (SSA), живучесть
считать тривиально, а `rcc` от этого упрощается кратно.

## 6. Runtime и «ОС»

ОС не нужна: компилируемая программа = код + статическая libc, всё вызывается напрямую,
`INT`-системные вызовы не используем (в модели они и так останавливают машину).

- `crt0`: точка входа образа (`0x0001_0000`): инициализация `r15` (стек с конца RAM),
  `call main`, результат в код возврата... модельный стоп — `RET` в конец программы,
  `rasim` трактует `RETI`/выход как успех; argv пока пустой, argc=1;
- libc (компилируется нашим же компилятором + часть на `.rasm` поверх имеющегося
  `samples/lib/uart.rasm`): `getchar/putchar/gets`, `puts/printf` (`%d %u %x %s %c`,
  без float), `malloc` (bump-alloc поверх RAM), `strlen/strcpy/strcmp/memcpy/memset`,
  целочисленное деление (см. раздел 4);
- аргументы командной строки, файлы — позже, вместе с ОС и вектором syscall `0x4`.

## 7. Золотые тесты

Как и договорено в emulator-architecture.md (M3): тесты компилятора гоняются на эмуляторе.

```
tests/RiscA.Rcc.Tests/Golden/
   <имя>.qbe          вход IL (пишется руками; потом и как вывод cproc)
   <имя>.expected     ожидаемый вывод + код возврата
```

Прогон: наш `rcc` → `.rasm` → `rasm` → `.bin` → `rasim` (режим скрипта с `--stdin`); контроль того же IL —
`qbe -o out.s && cc out.s && ./a.out` в WSL (эталон поведения самого IL-программиста).
Первые сюжеты: hello (data+LDI), эхо-повтор UART, цикл-sum, fib (call/ret/стек),
gcd (ветки/сравнения), таблица строк (`dw` меток).

| **A1** ✅ | фиксапы, `li/la/j`, пулы, петля релаксации в `rasm` + тесты | выполнено: 383 теста зелёны, «далёкие» переходы собираются и исполняются в эмуляторе, образцы `samples/` побайтово не изменились; детали — `assembler-architecture.md`, 6.6–6.7 |
| **A2** | в `rasm`: называемые слоты + авто-пролог/эпилог (`.func name(…)`, `.end`), выходы `ret x` / `ret` (один эпилог на область), `call f(a, b)` + стековые аргументы по ABI, имена-переменные + linear-scan регаллок со спиллом и коалесценцией | прежние тесты зелёны, `samples/` побайтово идентичны (без имён механизмы молчат); план — `assembler-architecture.md`, раздел 7 |
| **M3.0** | `RiscA.Rcc` (C#): читает подмножество IL (`data`, `function`, линейный код, alloc/load/store, add/sub/mul/and/or/xor, `csltw/cultw/ceqw`+jnz, call/ret), выдаёт `.rasm` | golden: hello, sum-цикл, gcd |
| **M3.1** | struct/union через смещения, глобальные `data`, пул констант, трамплины CALL | golden: таблица строк, fib |
| **M3.2** | `__udivsi3` runtime, libc-минимум (регаллок уже сделан в A2 в `rasm`) | компилируется и работает простейшая консольная утилита уровня cat/wc |
| **M3.3** | variadic+printf с `%`, `blit`, peephole; подключение cproc как реального фронтенда | реальная open-source утилита (маленькая, без float/64-бит) |

## 9. Риски и открытые вопросы

1. **~~cproc недоступен~~ — решено**: домашний сайт мёртв, но найдено и работает официальное
   зеркало автора `github.com/michaelforney/cproc`; собрано, IL получены (раздел 2). Флаг
   вывода IL в master — `-emit-qbe`. Важно для окружения: из WSL в github не проходит ни
   `git clone`, ни `curl` (TCP 443 не поднимается), а из Windows — качается; архивы тянуть
   Windows-curl'ом, сборку делать в WSL из `/mnt/c/...`.
2. **IL и ILP32 — уточнено**: ILP32-диалект существует и получен (форк `michg/cproc`,
   цель `rv32`, см. раздел 3). Открытый вопрос — только база фронтенда (форк vs порт
   таргета в upstream), решение на M3.0.
3. **Псевдокод-расширения QBE**: `blit`, `env`-параметры, `vastart/vaarg` — поддерживаем
   подмножество; всё остальное — явная ошибка «not supported yet», не тихий сбой.
4. **Вендоринг**: куда кладём cproc/qbe (`third-party/` vs отдельный репозиторий) — решить
   к M3.0; лицензии MIT, ограничений нет.
5. Карта символов (`rasm -s`, M2) должна покрывать имена функций бэкенда — формат уже
   рассчитан на это (emulator-architecture.md, раздел 7).
